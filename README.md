# 棱柱 USDZ 导出器

一个纯前端工具：调出一个横躺的 N 棱柱（N = 3–12，长轴沿 X，多边形端面朝左右），
给每个侧面单独贴图并在 3D 上直接拖拽定位，端面用纯色，导出成 USDZ 拿去 Keynote /
AR Quick Look 用。图片不上传任何服务器。

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
```

## 已实现

**阶段 1 — 跑通链路**
- 几何：棱柱横躺，长轴 = X，两个多边形端面在 ±X（左右两侧）。每个侧面一个独立 `Mesh` +
  独立 `MeshStandardMaterial`，端面各一个 mesh 用扇形三角化。没有用共享网格 + GeomSubset，
  Keynote 对「一个 mesh 一个材质」的支持最稳。
- 单位是米，`metersPerUnit = 1`，`upAxis = Y`，默认 10cm 长、外接圆半径 5cm。
- 侧面顶点整圈偏移半个扇区，face 0 的面心正对 +Z —— 也就是打开工具时正对着你的那个面。
- 贴图的 u 沿棱柱长度方向（左右），v 沿圆周方向（上下），所以每个面转到正面时图都是正的。
- 贴图烘焙：所有调整只改一张离屏 canvas 的绘制参数，UV 永远是干净的 0→1 满铺。
- 预览和导出共用同一张 canvas（`CanvasTexture` 包的就是它，`USDZExporter` 读的也是它），
  两者在物理上不可能不一致。
- 「填充纯色」按钮：一键给每个面填一张纯色图（只有底色，不带编号），导出后可以直接在 Keynote 里
  核对多 mesh 多材质有没有错位 —— 这是阶段 1 就该验掉的风险。

**相机与旋转**
- 相机是固定的：位置永远在 +Z 轴上正对物体，只在几何参数变化或窗口 resize 时按包围球重算距离，
  保证物体始终占满画面。没有 orbit、没有推拉。
- 拖拽转的是物体本身：左右拖绕世界 Y 轴，上下拖绕棱柱自己的长轴（像滚擀面杖那样把各个面滚上来），
  两个方向都不设限位，可以一直转。松手后有轻微阻尼收尾。
- 「正对当前面」把选中的面转到正对相机（yaw 归零、绕长轴转到该面的面心角），贴图定位时最好用；
  「重置角度」回到默认的微侧视角。两者都走最短路径，不会绕远路。
- 视口里的旋转纯粹是给人看的：导出时会把旋转临时归零（`runCanonical`），usdz 里的模型永远是正的。

**阶段 2 — 交互**
- 3D 上直接拖拽贴图：用 ray-plane 求交，不是屏幕像素换算。透视被自动处理掉，
  鼠标始终粘在贴图的同一个点上，手指拖出面的边界也不丢追踪。
- 滚轮 / 双指捏合缩放，以光标（捏合时是双指中点）所在位置为锚点，不是以面心。
- 缩放范围 1.0–8.0，offset 会被夹在「图片仍然盖满整个面」的范围内，永远不会露出背景色。
- 面选中高亮、悬停高亮、缩略图列表与视口双向同步。
- 拖图片进视口，落在哪个面就贴到哪个面；拖到空白处按文件名排序依次分配到 face 0、1、2…
- 减少边数时多出来的面，贴图数据保留在内存里，加回去就恢复。
- 参数和每个面的 transform 存 localStorage（图片本体不存）。

**阶段 3 — 颜色**
- 「伪 unlit」开关：导出前把 diffuse 压黑、贴图挂到 emissive 通道，
  Keynote 的环境光几乎影响不到颜色。代价是完全没有明暗、棱之间看不出转折。
  **视口预览会同步切换**，所以开关打开后看到的就是 Keynote 里会看到的。默认关闭。
- **颜色预补偿 + 自动标定**：把 Keynote 的偏色反解成一条曲线，导出时给贴图套上它的逆运算。

### 内置校准档

`BUILT_IN_PROFILE`（`src/lib/color.ts`）是 2026-09-05 用 **70 格色卡**在 Keynote 里实测出来的
（USDZ 模型渲染路径、灯光开着、补光拉满、正视），默认就生效，开箱不用配置。

开箱即用的水平（不做任何标定）：深红 `161,20,0` 差 0、中灰差 0、亮黄差 1、纯白差 11
（纯白那 11 是亮度天花板，物理上到不了）。

**这份档跨机器有效**，不是只对采集它的那台电脑管用。显示器色彩管理那一层在「标定」和
「验收」里同时出现，会互相抵消，剩下的是纯粹的 Keynote 变换（软件行为）。
需要重新标定的只有两种情况：换 Keynote 大版本，或者改了补光 / 灯光开关。

**模型：3×3 矩阵 + 每通道一条 5 节点单调曲线。** Keynote 干了两件事 —— 色域错位
（饱和色被推得更艳，饱和黄的蓝通道直接夹到 0）和一条 S 型明暗曲线（暗部压、中间提、高光收）。
矩阵吃前者，曲线吃后者，缺一不可。

模型的每个选择都是拿真实测量数据交叉验证选出来的，不是拍脑袋：

| 模型 | 交叉验证误差（满量程 255） |
|---|---|
| 不校正 | 23.8 阶 |
| 3×3 矩阵（线性光空间） | **27.2 阶 —— 比不校正还差** |
| 3×3 矩阵（sRGB 编码空间） | 17.9 阶 |
| 二次多项式 10 项 | 38.0 阶（过拟合） |
| **矩阵 + 5 节点曲线** | **13.9 阶** |

两个反直觉的结论：**在线性光空间里拟合会越校越歪**（亮样本权重过大，暗部编码回来误差被放大）；
**加参数不一定更好**，二次多项式在 24 个色块上严重过拟合。曲线节点数也是这么定的，
5 个节点的泛化误差比 7 个和 9 个都好。

两次独立截图测出来的数据完全一致（灰阶 0→16、51→47、102→108、153→164、204→201、255→225，
小数点后三位都对得上），说明 Keynote 的偏色是确定性的，剩下的 13.9 阶是 24 个色块能支撑的
模型能力上限，不是测量噪声。要再往下压得加色块数量。

一个补不回来的地方：饱和黄 (253,190,46) 需要往贴图里写红 > 255 才能抵消，写不进去，
最终会显示成 (247,190,46) —— 差 6 阶，肉眼看不出来。

### 重新校准（色卡流程）

逐通道曲线只能修「变暗 / 变灰」，修不了色域错位 —— 那是通道之间的混合，需要 3×3 矩阵。
靠肉眼比对更是不可能。所以主路径是导一张已知颜色的色卡进 Keynote，截图传回来，直接测量。

1. 点「导出色卡 USDZ」，拖进 Keynote，正对着截一张图（截图里要能看到完整的粉色边框）。
2. 把截图拖回工具里的第二个方框。

工具会按品红外框自动定位色卡（对缩放、边距、背景都不敏感），量出 24 个色块的实际颜色，
然后在**线性光**下解一个仿射模型：

```
y = M · x + b        M 是 3×3，b 是环境光抬升
```

这个模型同时吃下色域错位（M 的非对角项）、曝光（对角项）和环境光（b）。
导出时套用它的逆 `x = M⁻¹(y - b)`。被夹到 0 / 255 的样本对该通道没有信息量，拟合时会剔掉。

合成验证（把色卡按「sRGB 被当成 P3 显示 + 环境光抬 0.02」处理，再加背景边距和缩放模拟截图）：
识别成功，拟合残差 0.0009，补偿回环误差在 0～2/255 之间 —— 包括最难的那个饱和黄
(253,190,46)，写进贴图变成 (241,189,64)，进 Keynote 显示回 (253,190,48)。

### 界面

颜色这一栏只有两个开关和一个折叠项：

- **Keynote 颜色优化** —— 默认开着，用内置校准档，不用配置。
- **关掉 Keynote 的灯光影响** —— 打开后面的颜色只由贴图决定、不受角度影响，代价是没有明暗立体感。
  内置校准档是灯光开着测的，改了这个开关界面会提示需要重测。
- **重新校准（一般不用）** —— 折叠着，只有换 Keynote 版本、换显示器或者改了灯光开关才需要。

早期版本里的逐通道曲线标定、sRGB→P3 开关、曝光/对比度/饱和度滑杆都已经删掉了：
矩阵 + 曲线模型完全包含它们的能力，留着只是让界面变复杂。

## 交互约定

| 操作 | 结果 |
|---|---|
| 点未选中的面 | 选中它（这次拖拽同时也会转物体） |
| 在**已选中**且有图的面上拖动 | 移动贴图 |
| 在空白处 / 未选中的面上拖动 | 转物体（相机不动） |
| 按住 Shift 在选中面上拖动 | 强制转物体 |
| 滚轮悬停在选中面上 | 以光标为锚点缩放贴图 |
| 滚轮在其他地方 | 什么都不做（相机是固定的） |

## 几个实现上的选择

- **侧面宽高比 = 长度 / 弦长**。棱柱横躺之后，侧面的长边是棱柱长度、窄边是圆周弦长；
  边数从 3 加到 12 时弦长会一直变窄，界面上实时标着当前比例和贴图画布尺寸，
  你能立刻知道该配什么形状的图。
- **贴图分辨率**：长边固定 512 / 1024 / 2048，短边按侧面宽高比算。短边不足 256 时整体等比放大，
  长边超 2048 时整体等比缩小 —— 始终保持比例，因为 canvas 宽高比一旦和面的宽高比不一致，
  贴图就会在面上被拉伸。
- **`USDZExporter` 的 `maxTextureSize` 默认是 1024**，会把 2048 的贴图偷偷降采样，
  导出时显式传了当前分辨率。
- **导出的是 `viewer.prism` 这一个分组**，选中描边、网格地面、灯光都不在它里面，
  天然不会被带进文件，不需要「导出前记得隐藏」这种约定。
- **未覆盖区域填纯色不留透明**：Keynote 对带 alpha 的贴图渲染行为不好预测。
- 侧面 `roughness = 0.9`：高粗糙度压制高光对贴图颜色的干扰。

## 已知风险 / 下一步

1. **Keynote 颜色偏差** —— 已经有伪 unlit 开关 + 自动标定的预补偿两招。剩下的硬限制是
   被环境光抬起来的黑位补不回来，以及 PBR 模式下不同朝向的面偏差量不同。
2. **文件体积** —— 12 面 × 2048 会很大。工具条上有实时预估（按 PNG 实际编码算，不是拍脑袋）。
   贴图在 USDZ 里是 STORED 不再压缩，预估值和最终文件很接近。
3. **`USDZExporter` 的能力边界** —— 它只导 PBR，不支持真正的 unlit。如果颜色调不到位，
   兜底方案是手写 usda 文本 + 自己打 zip 包，换取对 unlit、色彩空间、材质细节的完全控制。
